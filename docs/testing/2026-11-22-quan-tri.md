## (C) Phân quyền và bảo mật quan sát được

| Kiểm tra                                                                 | Kết quả                                                                                                                                  |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/admin/users` không token                                    | **401** `UNAUTHENTICATED` "Vui lòng đăng nhập lại"                                                                                       |
| Token rác                                                                | **401** `UNAUTHENTICATED` "Phiên đăng nhập đã hết hạn"                                                                                   |
| Token khách hàng → `GET /admin/users` và `PATCH /admin/users/:id/status` | **403** `FORBIDDEN` "Bạn không có quyền thực hiện thao tác này"                                                                          |
| Token sau `POST /auth/logout` → `GET /auth/me`                           | **401** `UNAUTHENTICATED` "Phiên đăng nhập đã bị thu hồi" (thu hồi tức thì, không đợi hết hạn)                                           |
| Đăng ký kèm `"role":"ADMIN"`                                             | **400** `VALIDATION_FAILED` "Unrecognized key: role" (không tự nâng quyền được)                                                          |
| Body sai tên field (`login` thay vì `identifier`)                        | 400 `VALIDATION_FAILED`, có `details`                                                                                                    |
| Tài khoản bị admin khóa + đúng mật khẩu                                  | **403** `AUTH_ACCOUNT_LOCKED`                                                                                                            |
| Tài khoản bị admin khóa + sai mật khẩu                                   | **401** `AUTH_INVALID_CREDENTIALS` (không lộ trạng thái khóa khi sai mật khẩu)                                                           |
| Sai mật khẩu 6 lần liên tiếp (tài khoản test)                            | Lần 1–5: **401** `AUTH_INVALID_CREDENTIALS`; lần 6: **429** `RATE_LIMITED` "Bạn đã nhập sai quá nhiều lần. Vui lòng thử lại sau 15 phút" |
| Sau đó đúng mật khẩu (viết hoa email)                                    | Vẫn **429** → khóa tạm theo identifier đã chuẩn hóa (không lách bằng đổi hoa/thường)                                                     |
| Chặn vai trò trên frontend                                               | Khách vào `/admin/*` → về `/`; admin vào `/`, `/technician` → về `/admin/users`                                                          |
| Admin tự khóa mình                                                       | UI không hiển thị nút. Code `users-admin.service.ts` chặn bằng 403 (không thử qua API để tránh khóa tài khoản mẫu)                       |

Ghi chú từ code (không thao tác được): ngưỡng `LOGIN_MAX_FAILURES = 5`, `LOGIN_LOCK_SECONDS = 900` (Redis, theo identifier, không theo IP); throttle theo IP: login 10/phút, register 5/phút, refresh 30/phút. Khóa/mở khóa ghi audit `admin.user_locked|unlocked` kèm `reason`; đăng nhập sai ghi `auth.login_failed`. "Mở khóa" của admin **không** xóa bộ đếm khóa tạm 15 phút (hai cơ chế tách biệt). Khóa tạm theo identifier nghĩa là ai cũng có thể làm khóa tạm tài khoản người khác 15 phút bằng 5 lần sai. Việc thu hồi phiên đang mở khi bị khóa chưa kiểm chứng bằng thao tác (tài khoản test không đăng nhập lúc bị khóa).

Tài khoản test hiện ở trạng thái **Hoạt động** nhưng đang bị khóa tạm 15 phút do bước thử sai mật khẩu (tự hết hạn).

## (D) Endpoint backend thật (Swagger `/api/docs-json`)

| Method | Path                            | Quyền                                                         |
| ------ | ------------------------------- | ------------------------------------------------------------- |
| GET    | /health/live                    | public                                                        |
| GET    | /health/ready                   | public                                                        |
| POST   | /api/v1/auth/register           | public                                                        |
| POST   | /api/v1/auth/login              | public (body `identifier`, `password`)                        |
| POST   | /api/v1/auth/refresh            | public (cookie refresh)                                       |
| POST   | /api/v1/auth/logout             | Bearer                                                        |
| POST   | /api/v1/auth/logout-all         | Bearer                                                        |
| GET    | /api/v1/auth/me                 | Bearer                                                        |
| GET    | /api/v1/admin/users             | ADMIN; query `role,status,q,page,pageSize(≤100, mặc định 20)` |
| PATCH  | /api/v1/admin/users/{id}/status | ADMIN; body `{status, reason}`                                |

Chỉ có module `identity` trong `backend/src/modules`. Schema Prisma đã có file booking/catalog/payments/technician/profile/platform nhưng chưa có endpoint nào.

## (E) Admin sàn cần mà chưa có

- Không xem/quản lý booking, điều phối/gán KTV, đối soát thanh toán, hoàn tiền, bản đồ realtime (3 tab đều placeholder; backend không có endpoint).
- Không quản lý danh mục dịch vụ/bảng giá.
- Không tạo tài khoản KTV (cấp mã `TECH-xxx`), không sửa hồ sơ/đổi vai trò/đặt lại mật khẩu cho user.
- Không xem audit log (dù lý do khóa "được ghi vào audit log"); bảng không hiện lý do/thời điểm khóa.
- UI không có lọc theo trạng thái (API đã hỗ trợ `status`), không sắp xếp, không xem chi tiết user.
- Không có cách gỡ khóa tạm (sai mật khẩu) cho user; không thấy user nào đang bị khóa tạm.
- Không có dashboard số liệu (doanh thu, số booking, KTV online…), không thông báo/khiếu nại/đánh giá.
- Trạng thái rỗng/đang tải không có thông báo riêng; trên mobile cột hành động bị khuất.
- Không có 2FA cho admin (spec để sau MVP).
